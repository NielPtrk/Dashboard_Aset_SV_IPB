Saya sedang membangun web app “Aset SV IPB” untuk Sistem Informasi Manajemen Aset Sekolah Vokasi IPB. Desain UI existing sudah bagus dan sudah ada banyak halaman/menu/submenu/tabs, tetapi masalah fatalnya adalah seluruh data masih statis: angka KPI, warna badge, chart, table, filter, status, detail drawer, dan isi dashboard belum saling terhubung satu sama lain.

Tugas utama kamu:
REFactor / perbaiki sistem agar seluruh halaman menjadi data-connected, integrated, dan reactive berbasis satu sumber data utama, yaitu tabel Data Aset.

PENTING:
Ini bukan redesign visual.
Jangan mengubah tampilan besar-besaran.
Jangan mengganti sidebar, topbar, warna, typography, spacing, card, table, badge, button, tabs, atau layout utama yang sudah ada.
Fokus pada integrasi data, state management, data flow, computed metrics, relationship antar halaman, dan interaksi antar menu.

Tujuan akhir:
1. Data Aset menjadi single source of truth.
2. Semua dashboard mengambil data dari Data Aset dan data transaksi terkait.
3. Semua KPI, chart, badge, table, dan jumlah data dihitung otomatis dari dataset, bukan hardcoded.
4. Klik baris di Data Aset harus membuka detail aset yang konsisten dengan data yang sama.
5. Klik aset dari dashboard, stock opname, maintenance, mutasi, pengadaan, lokasi, PIC, atau dokumen harus mengarah ke detail aset yang sama.
6. Perubahan data di satu modul harus memengaruhi modul lain secara logis.
7. Sistem harus terasa advanced, data-driven, kolaboratif, dan terintegrasi, bukan sekadar mockup statis.

==================================================
E. BUAT DATA SELECTOR / COMPUTED METRICS
==================================================

Buat layer selector/helper function untuk menghitung semua kebutuhan.

Wajib ada function seperti:

1. getAssetById(asset_id)
Mengambil detail aset berdasarkan asset_id.

2. getAssetByTag(kode_tag_aset)
Mengambil aset dari hasil scan barcode/QR.

3. getAssetsByCategory(jenis_aset)
Filter aset PM/ATB/ATL/AL.

4. getAssetsByUnit(nama_unit)
Filter aset berdasarkan unit.

5. getAssetsByRoom(kode_ruangan)
Filter aset berdasarkan ruangan.

6. getAssetsByPIC(nama_pic)
Filter aset berdasarkan PIC.

7. getAssetsByCondition(status)
Filter aset berdasarkan kondisi sistem.

8. computeTotalAssets()
Menghitung total aset.

9. computeTotalBookValue()
Menjumlahkan nilai_buku.

10. computeTotalAcquisitionValue()
Menjumlahkan harga_perolehan / harga_diterima.

11. computeTotalDepreciation()
Menjumlahkan penyusutan / akumulasi_penyusutan.

12. computeStockOpnameProgress()
Menghitung persentase aset terverifikasi.

13. computeMissingAssets()
Menghitung aset dengan status opname hilang/tidak ditemukan.

14. computeUnverifiedAssets()
Menghitung aset belum dicek / belum opname.

15. computeAssetsWithoutClearLocation()
Menghitung aset dengan status_kejelasan_lokasi kosong / tidak jelas / perlu verifikasi.

16. computeAssetsWithoutPIC()
Menghitung aset tanpa nama_pic.

17. computeMaintenanceOverdue()
Menghitung aset dengan jadwal_maintenance_berikutnya < tanggal hari ini.

18. computeTopMaintenanceCost()
Ranking aset/unit dengan total_biaya_maintenance tertinggi.

19. computeTopDamagedAssets()
Ranking aset dengan total_frekuensi_maintenance tertinggi.

20. computeConditionScore(asset)
Menghitung skor kondisi berdasarkan:
- kondisi_legacy
- kondisi_fisik_opname_terakhir
- sisa_masa_manfaat
- total_frekuensi_maintenance
- total_biaya_maintenance
- tingkat_kerusakan_terakhir
- downtime_terakhir_jam

21. computeReplacementPriority(asset)
Menghitung prioritas penggantian dari:
- sisa_masa_manfaat rendah/habis
- kondisi buruk
- maintenance tinggi
- biaya maintenance tinggi
- downtime tinggi
- nilai buku rendah atau aset sudah tidak ekonomis

22. computeIdleAssetRate()
Menghitung aset dengan status_penggunaan_aset = idle / total aset.

23. computeRoomUtilization()
Menghitung rasio aset terhadap kapasitas ruangan.

24. computeRoomsLackingAssets()
Menghitung ruangan yang kekurangan aset berdasarkan kategori_ruangan, kapasitas_orang_ruangan, dan rule backend.

25. computeProcurementNeed()
Menghitung kebutuhan pengadaan dari:
- aset rusak berat
- aset melewati masa manfaat
- ruangan kekurangan aset
- aset yang tidak bisa diperbaiki
- kebutuhan unit
- setelah mempertimbangkan aset idle yang bisa direalokasikan

26. computeDataQualityScore(asset)
Menghitung kualitas data:
- lengkap
- perlu verifikasi
- tidak lengkap
- konflik data

==================================================
F. RULE UNTUK STATUS DAN WARNA BADGE
==================================================

Semua badge status harus dihitung dari data, bukan warna statis.

Gunakan rule:

Status Aset:
- Baik: kondisi baik, tidak overdue, sisa masa manfaat cukup, tidak sering rusak.
- Perlu Monitoring: sisa masa manfaat rendah atau maintenance mulai sering.
- Rusak Ringan: kondisi fisik opname rusak ringan atau tingkat kerusakan ringan.
- Rusak Berat: tingkat kerusakan berat/kritis atau kondisi opname rusak berat.
- Prioritas Penggantian: sisa masa manfaat habis + biaya maintenance tinggi + sering rusak.

Status Opname:
- Terverifikasi: status_opname_terakhir = Terverifikasi.
- Belum Dicek: tanggal_opname_terakhir kosong.
- Selisih: status_lokasi_opname_terakhir = Tidak Sesuai / Berbeda.
- Tidak Ditemukan: status_opname_terakhir = Hilang / Tidak Ditemukan.
- Perlu Verifikasi: data konflik atau lokasi tidak jelas.

Status Maintenance:
- Scheduled: jadwal maintenance masih nanti.
- Due Soon: jadwal maintenance dalam 30 hari.
- Overdue: jadwal maintenance sudah lewat.
- Dalam Proses: tiket perbaikan aktif.
- Selesai: tiket sudah selesai.

Status Mutasi:
- Draft
- Menunggu Persetujuan
- Disetujui
- Ditolak
- Selesai

Status Pengadaan:
- Draft
- Menunggu Persetujuan
- Disetujui
- Dalam Pengadaan
- Selesai
- Ditolak

Status Data Quality:
- Lengkap
- Perlu Verifikasi
- Tidak Lengkap
- Konflik Data

Warna badge harus mengikuti status:
- Hijau soft: baik, aktif, selesai, terverifikasi.
- Kuning soft: menunggu, due soon, perlu verifikasi.
- Biru soft: dalam proses, scheduled.
- Merah soft: rusak berat, overdue, ditolak, tidak ditemukan.
- Abu soft: draft, belum dicek, tidak lengkap.

- total biaya maintenance lebih kecil dari biaya maintenance terakhir
- latitude ada tetapi longitude kosong

Tampilkan Data Quality indicator di:
- Data Aset
- Detail Aset

- Top Unit = group assets by nama_unit
- Top Maintenance = group by unit/aset total_biaya_maintenance

- Prediksi Perbaikan = computeConditionScore + computeMaintenanceRisk

- Rekapitulasi = group by filter

- Valuasi = nilai_buku dan harga_perolehan
- Penyusutan = penyusutan dan akumulasi
- Aset Bernilai Tinggi = sort nilai_buku desc
- Biaya per Unit = group nilai aset by unit

Dashboard Kondisi:
- Kualitas Aset = computeConditionScore
